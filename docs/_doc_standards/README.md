# 文档写作标准索引

本目录存放仓库内**中文技术文档**的写作标准。按「全局通用 + 按类型/路径的专项」分层；执行撰写或评审时，先满足全局底线，再对照专项。

---

## 全局与专项的关系（写清四件事）

1. **分层**  
   - [`00_overall.md`](00_overall.md)：全局通用——全仓库文档的共同规则，不规定某一类文档的固定目录。  
   - [`01_technical_design.md`](01_technical_design.md)～[`04_misc.md`](04_misc.md)：专项——各自只约束一类文档的结构、字段或流程。  

2. **对齐**  
   专项标准须与 `00_overall` **一致**；可在 00 未覆盖处加严、加细，**不得**推翻 00 中的底线。

3. **写某类文档时以谁为主**  
   同一话题上，若专项已约定「这类文档怎么组织」，以专项为主；若话题只在 00 中出现（如禁止编造证据），**所有类型**均须遵守。

4. **条文矛盾时**  
   若 00 与专项不能同时满足，以 **`00_overall` 为准**，并修订专项；不以「习惯写法」替代。

**说明**：「先读 00 再读专项」是**阅读顺序**；「矛盾时以 00 为准」是**维护规则**。二者不是同一句话里的概念，不要混用。

## 怎么选专项标准

- **核心问题是“系统该怎么设计、为什么这么设计”**：看 [`01_technical_design.md`](01_technical_design.md)。  
- **核心问题是“本轮做什么算完成、计划怎么排、现在做到哪”**：看 [`02_implementation-tracking.md`](02_implementation-tracking.md)，即使文件路径在 `design/` 下也一样。  
- **仍处于草稿、预研、proposal、个人或小组笔记阶段**：先看 [`04_misc.md`](04_misc.md)；一旦该文开始作为共同评审依据或实施依据，应升级到 `01` 或 `02`。

## 与仓库内其他专项标准的关系

若仓库内某个业务域、子系统或目录另有补充文档标准，则撰写该范围内文档时，除遵守本目录标准外，还应遵守对应补充标准中的术语、命名与场景化约定；若补充标准与 `00_overall` 或相应专项标准冲突，以后两者为准，并应回头修订补充标准。
